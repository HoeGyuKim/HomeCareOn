# 하자보수 민원 접수 AI 시스템

아파트·공동주택 하자보수 전화 민원을 AI가 분석해 저장하고, 조건에 맞는 보수 업체에 자동 배정·전달하는 관리자 웹 애플리케이션입니다.

## 실행 방법

```bash
npm install      # 최초 1회
npm run dev      # 개발 서버 → http://localhost:3000
```

운영 모드로 실행하려면 `npm run build` 후 `npm start`를 실행합니다.

별도 설정이 없으면 **테스트 모드**(메모리 저장소 + 규칙 기반 통화 분석)로 동작합니다. 서버를 재시작하면 데이터는 초기 테스트 데이터로 돌아갑니다.

## 화면

| 경로 | 기능 |
|---|---|
| `/` | 대시보드: 통계 카드, 관리자 확인 대기 알림, **서울 구별 처리율(타일 지도 + 순위)**, 최근 민원, 유형별 현황 |
| `/complaints` | 민원 목록: 검색, 자치구·상태·유형·긴급도 필터 |
| `/complaints/[id]` | 민원 상세: 진행 단계, 자동 재배정, 수동 배정, 상태 변경, 처리 이력 |
| `/complaints/new` | 민원 직접 등록 (사진 첨부 가능) |
| `/call-simulator` | AI 통화 접수 테스트: 가상 통화 → 분석 → 접수 |
| `/contractors` | 업체 관리: 등록, 수정, 삭제, 계약 여부와 업무 가능 여부 전환 |

## AI 전화 접수 (`/call-simulator` → AI 상담원 통화)

AI 상담원이 민원인과 대화하며 접수합니다. 마이크(Chrome·Edge 음성인식)로 말하거나 직접 입력할 수 있고, 상담원 답변은 음성으로 읽어 줍니다.

1. 하자 내용과 원인을 듣고, 「시설물 수선비 비용부담 기준(2026)」과 「주택관리규정 시행내규」로 비용 부담 주체를 판정합니다.
   - **접수 가능**: SH공사 부담 / 관리비(공용부분) / 현장 확인 후 결정
   - **접수 불가**: 입주자 부담(소모품·파손·막힘·동파 등) / 허용 안 됨(구조 변경·신규 설치). 이 경우 안 된다고 분명히 말하고 근거를 알려 주며, 개인정보를 묻지 않고 접수하지 않습니다.
2. 접수 가능하면 이름(2~4글자) → 연락처(010-1234-5678) → 단지 → 동·호수를 하나씩 묻고 형식을 확인합니다.
3. 내용을 읽어 주고 확인을 받은 뒤 접수하고 업체를 자동 배정합니다.

서버가 판정과 형식을 다시 검사하므로, AI가 실수하더라도 '접수 불가' 건이나 형식이 틀린 정보는 저장되지 않습니다.

- `ANTHROPIC_API_KEY`가 있으면 **Claude 상담원**이 동작합니다. 기준표와 내규 원문을 읽고 판정합니다.
- 키가 없으면 **테스트용 상담원**이 동작합니다. 정해진 순서로 묻고 키워드 규칙(`src/lib/policy/rules.ts`)으로 판정합니다.
- 기준 원문(`src/lib/policy/standard-text.ts`)은 PDF에서 자동 생성한 파일입니다. 기준이 개정되면 다시 생성해야 합니다.
- 실제 전화 연동 시에는 음성인식 결과를 `POST /api/agent` `{ sessionId, message }`로 보내고, 응답의 마지막 상담원 메시지를 음성합성으로 들려주면 됩니다.

## 서비스 지역

서울특별시 25개 자치구 전용입니다. 단지의 지역과 업체의 담당 지역은 모두 자치구 이름(예: `강남구`)으로 저장합니다. 자치구 목록과 타일 지도 배치는 `src/lib/seoul.ts`에 있습니다. 업체 담당 지역에는 서울 자치구만 지정할 수 있습니다.

**구별 처리율**은 해당 구의 처리 완료 건수를 전체 접수 건수로 나눈 값입니다. 대시보드에서 구를 누르면 그 구의 민원 목록(`/complaints?district=강남구`)으로 이동합니다.

## 자동 배정 규칙 (`src/lib/services/assignment.ts`)

1. 하자 유형이 업체의 담당 분야와 일치해야 합니다.
2. 단지 지역이 업체의 담당 지역에 포함되어야 합니다.
3. 계약된 업체이면서 업무 가능 상태여야 합니다.
4. 후보가 여러 곳이면 현재 진행 건수가 가장 적은 업체를 배정합니다.
5. 후보가 없으면 **관리자 확인 대기**로 처리합니다. 관리자는 상세 화면에서 수동으로 배정할 수 있습니다.

처리 상태는 접수 → 업체 배정 → 작업 예정 → 작업 중 → 처리 완료 순으로 진행합니다.

## 외부 서비스 연결

`.env.example`을 `.env.local`로 복사한 뒤 값을 채우고 서버를 재시작합니다.

- **Claude API**: `ANTHROPIC_API_KEY`를 설정하면 통화 분석에 Claude(`claude-opus-5-5`)와 구조화 출력을 사용합니다. 호출에 실패하면 규칙 기반 분석으로 자동 전환합니다.
- **Supabase**: `supabase/schema.sql`을 SQL Editor에서 먼저 실행합니다. 그다음 `NEXT_PUBLIC_SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`를 설정하면 DB 저장소로 전환됩니다.
- **실제 전화 연동**: 전화·STT 시스템의 통화 종료 웹훅이 `POST /api/calls/intake`로 `{ "transcript": "...", "callerPhone": "010-..." }`을 보내도록 설정합니다. 분석, 저장, 배정, 업체 전달이 한 번에 처리됩니다.
- **업체 알림**: `src/lib/services/notification.ts`의 `sendToContractor`를 실제 이메일·문자·알림톡 발송 코드로 바꿉니다. 현재는 서버 로그에만 기록합니다.
