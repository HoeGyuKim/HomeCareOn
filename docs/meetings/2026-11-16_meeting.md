## 2. 주요 논의 및 결정 사항

### 1) 상용 LLM API 활용 및 개발 모델 검토
* SH 시설물 민원 접수 및 수선유지 기준표는 대외비/보안 사항이 아니므로, 로컬 폐쇄망 모델 대신 **상용 LLM API(Gemini, Claude 등)**를 연동하여 개발하기로 합의.
* 토큰 비용 및 모델 가성비와 관련하여, 권승민이 구독 중인 Gemini 유료 플랜(월 3만 원 상당)의 토큰 지원량 및 Antigravity 연동 효율성을 공유함.

### 2) 파트별 역할 및 데이터 연계 방식 구체화
* **대화 엔진 (권승민)**:
  - 거주자의 음성(STT)을 텍스트로 변환하고, LLM을 통해 대화 맥락에 맞게 응답 생성 후 음성(TTS)으로 답변하는 파이프라인 구축.
  - 사용자와의 대화 내용(동·호수, 증상, 에러코드 등)을 텍스트 형태로 정제하여 검색/판정 모듈로 전달.
* **RAG 검색 엔진 (조준혁)**:
  - 대화 엔진에서 넘어온 증상/에러 텍스트와 시설물 수선비용 기준 일람표를 분석하여, `세대·설비 매칭`, `비용 부담 주체 판정` 결과를 도출하는 정형화된 검색/판정 모델 개발.
* **관리자 웹 & 백엔드 (김회규)**:
  - FastAPI 기반 서버, 세대/설비 DB, 티켓 생성 및 접수 내역을 조회하고 처리 상태를 관리하는 SH 직원용 관리자 웹 개발.

### 3) 협업 방식 및 소통 규칙
* **회의록 분리**: 기존 `team_comment` 파일은 매일 빠른 피드백과 질의응답을 주고받는 용도로 사용하고, 정식 회의 내용은 `docs/meetings/` 아래에 별도 문서로 분리하여 관리하기로 합의.
* **README 문서 공유**: 김회규가 작성한 프로젝트 개요 및 명세를 팀원들이 검토하고 필요시 보완하기로 함.
