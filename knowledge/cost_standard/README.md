# 시설물 수선비 비용부담 기준 (RAG 데이터)

SH 「시설물 수선비 비용부담 기준(임대아파트 및 기타주택) 2026」을 RAG와 비용 부담 판정에 쓰기 좋게 구조화한 데이터입니다.
원본은 `knowledge/sources/`에 있고, 이 폴더의 파일은 `aliases.csv`를 빼고 모두 스크립트로 생성합니다. **직접 고치지 말고 재생성하세요.**

## 파일

| 파일 | 내용 | 건수 |
|---|---|---|
| `items.jsonl` | [별표2] 일람표. 항목 1개 = 1줄. 원인 키워드 분해와 임베딩용 문장 포함. **RAG 입력** | 457 |
| `items.csv` | 같은 내용을 사람이 검수하기 좋게 펼친 표 (엑셀로 열림) | 457 |
| `principles.jsonl` | 본문 조항(제1~3장), [별표1] 용어 정의, 일람표 주석 | 40 |
| `aliases.csv` | 항목별 구어 표현 (`id`, `별칭`). **사람이 채우는 파일**, 재생성해도 유지됨 | 0 |

[별표3] 손해조정기준과 [별표4] 세대점검표는 퇴거 시 원상복구용이라 넣지 않았습니다.

## items.jsonl 필드

```json
{"id": "1-9-02", "구역": "전용", "대분류": "건물 전용부분", "중분류": "개별보일러",
 "항목": ["단위세대 개별보일러 시설물", "PCB"],
 "임대인부담_원문": "작동불량 교체", "임차인부담_원문": "파손,동파",
 "임대인부담": [{"원인": "작동불량 교체", "조건": null, "시점": null}],
 "임차인부담": [{"원인": "파손", "조건": null, "시점": null}, {"원인": "동파", "조건": null, "시점": null}],
 "비고": "", "준용": null, "별칭": [],
 "출처": "... [별표2] 건물 전용부분 > 개별보일러", "기준연도": 2026,
 "text": "건물 전용부분 > 개별보일러 > 단위세대 개별보일러 시설물 > PCB: 임대인(SH) 부담 - 작동불량 교체. 임차인 부담 - 파손,동파."}
```

| 필드 | 설명 |
|---|---|
| `id` | `대분류번호-중분류번호-순번`. 문서 목차 번호를 따름 (예: `1-9` = 1. 건물 전용부분 > 9) 개별보일러) |
| `구역` | `전용`(세대 내부, 대분류 1) / `공용`(대분류 2~5). 공용부의 임차인 부담은 관리비 공동부담(조항 P10) |
| `항목` | 표의 항목 열을 위에서 아래로 (병합 셀을 풀어 상위 분류까지 포함) |
| `*_원문` | 표 셀 원문. 근거로 보여줄 때 사용 |
| `임대인부담`, `임차인부담` | 원문을 쉼표로 나눈 원인 목록. `조건`은 괄호 안 단서 원문 |
| `시점` | 입주일과 비교해야 하는 단서를 정규화한 값. `입주후1개월` / `입주시만` / `null` |
| `준용` | 다른 항목 기준을 따르라는 행 (예: 위생기구 → "1.건물 전용부분 4)화장실 준용") |
| `text` | 임베딩·검색용 문장. 별칭이 있으면 끝에 붙음 |

### 같은 원인이 양쪽에 있는 경우

`작동불량`처럼 같은 원인이 양쪽 칸에 모두 있으면, 보통 `시점` 단서로 갈립니다.

- 현관문 차임벨: 임대인 `작동불량(입주후 1개월내)`, 임차인 `작동불량` → 입주 1개월 안이면 SH, 그 뒤면 거주자
- 렌지후드: 임대인 `작동불량`, 임차인 `관리 부주의로 인한 작동불량` → 원인(부주의 여부)으로 갈림

`decide_liability()`는 세대 DB의 입주일과 `시점`을 비교하고, 그래도 갈리지 않으면 "점검 후 결정" 으로 안내해야 합니다.

## principles.jsonl

| 구분 | id | 내용 |
|---|---|---|
| 조항 | P01~P19 | 제1장 일반사항, 제2장 수선비 부담, 제3장 퇴거 시 원상복구 |
| 용어 | P20~P38 | [별표1] 노후, 작동불량, 파손, 망실 등 19개 정의 |
| 일람표 주석 | N01~N02 | 승강기 "유사 품목 준용", "6. 임대상가시설물: 아파트 기준 준용" |

판정 규칙에서 특히 쓰이는 조항:
- **P09** 고의·과실·사용상 부주의로 인한 전용부분 파손 → 임차인
- **P10** 공용부 소모성 지출 → 관리비 공동부담 (관리주체 소홀이면 관리주체)
- **P11** 지진·태풍·수해·한파 등 천재지변 → 임대인 (표의 `동파`보다 우선하는지는 팀에서 정해야 함)
- **P12** 명기되지 않은 사항 → 협의. AI가 단정하지 말고 직원 확인으로 넘김

## 검수 결과와 확인할 것

생성 시 다음을 확인했습니다.
- 일람표 표 38개의 데이터 행 457개가 빠짐없이 출력됨
- 모든 항목·부담 셀 문자열이 PDF 원문 텍스트에서 확인됨 (가운뎃점 `‧`→`·` 표기 차이 7건 제외)

사람이 원본과 대조해 확인해야 할 것:
- **`1-9-01` "가버너"**: 원문이 `가 버 너`로 자간이 띄워져 있습니다. "가스버너"의 오기인지 확인이 필요합니다.
- **한 칸에 두 항목**: `장판지 걸레받이`, `경첩 기타부착물`처럼 원문 셀 안에서 줄바꿈으로 나뉜 항목이 한 행으로 합쳐져 있습니다.
- **괄호 단서의 범위**: `변형, 손모, 부식 (입주시만적용)`처럼 단서가 맨 끝에 한 번만 붙은 경우, 스크립트는 마지막 원인(`부식`)에만 붙입니다. 실제로는 앞의 원인 전체에 걸릴 수 있습니다.
- **원인이 아닌 괄호**: `(예: 강제개방 등)`, `(못,앙카)`처럼 예시나 설명인 괄호도 `조건`에 들어가 있습니다. `시점`이 `null`이면 판정에는 영향이 없습니다.

## 별칭 채우기

거주자는 표의 용어("크리센트", "PCB")로 말하지 않으므로, 검색 정확도는 `aliases.csv`가 좌우합니다. 여러 표현은 `|`로 구분합니다.

```csv
id,별칭
1-1-12,창문 잠금장치|창문 손잡이|창문 걸쇠
1-9-02,보일러 기판|보일러 에러|보일러 전원이 안 들어옴
```

테스트 시나리오를 만들면서 검색에 실패한 표현을 여기에 추가하는 식으로 늘려 갑니다.
